# Makeheap

## Идея

В minheap значение каждого родителя не больше значений его детей.
В массиве дети вершины `i` находятся по индексам `2*i + 1` и `2*i + 2`,
а её родитель находится по индексу `(i - 1) // 2`. Обе функции переставляют
элементы в исходном списке и возвращают этот же список.

## Исполнение

`makeheap_n_log_n` поддерживает кучу в префиксе массива.
Следующий элемент добавляется на место листа. Пока он меньше родителя,
он меняется с ним местами. После каждого обмена возможное нарушение
перемещается на уровень выше. Когда элемент доходит до корня или
становится не меньше родителя, весь расширенный префикс образует кучу.

`makeheap` обходит внутренние вершины с конца массива к началу.
Листья уже образуют кучи из одного элемента. На момент обработки
вершины её дочерние поддеревья уже являются кучами. `sift_down` меняет
вершину с меньшим ребёнком, если тот меньше неё. После обмена поднятое
значение не больше обоих детей, а возможное нарушение остаётся
только на пути вниз. После обработки корня весь массив образует кучу.

## Визуализация

Для входа `[5, 2, 4, 1, 3]` два метода проходят такие состояния.

| Просеивание вверх | Префикс после вставки |
| --- | --- |
| Начальный элемент 5 | `[5]` |
| Вставить 2 | `[2, 5]` |
| Вставить 4 | `[2, 5, 4]` |
| Вставить 1 | `[1, 2, 4, 5]` |
| Вставить 3 | `[1, 2, 4, 5, 3]` |

| Просеивание вниз | Состояние массива |
| --- | --- |
| Просеять вершину 1 со значением 2 | `[5, 1, 4, 2, 3]` |
| Просеять корень 0 со значением 5 | `[1, 2, 4, 5, 3]` |

## Сложность

При вставке элемента с индексом `i` его путь до корня имеет длину
`⌊log₂(i + 1)⌋`. Поэтому сумма затрат по вставкам не превышает
`O(n log n)`. На убывающем входе каждый новый элемент является
новым минимумом и проходит весь этот путь. У последних примерно
`n/2` элементов глубина порядка `log n`, поэтому оценка достигается.

Для `makeheap` обозначим через `H(i)` высоту вершины `i` в рёбрах.
Время одного просеивания ограничено `O(1 + H(i))`. Для любого `h ≥ 1`
самый левый потомок вершины `i` на расстоянии `h` имеет индекс
`2ʰ(i + 1) − 1`. Он существует ровно тогда, когда этот индекс меньше
`n`. Значит, вершин высоты хотя бы `h` ровно `⌊n/2ʰ⌋`. Сумму высот
можно посчитать по уровням, учитывая каждую вершину высоты `H(i)`
один раз для каждого `h` от 1 до `H(i)`.

Базовые затраты на обход `⌊n/2⌋` внутренних вершин тоже линейны.
Вместе это даёт `O(n)`. Оба метода итеративны и используют
`O(1)` дополнительной памяти.

## Тесты

`test_makeheap.py` проверяет порядок между каждым родителем и ребёнком,
сохранение всех элементов и работу на месте. Есть случаи с пустым
массивом, одним элементом, повторами, отрицательными значениями
и неполным последним уровнем дерева.

## Замеры

В таблице медианы семи вызовов в миллисекундах. Перед каждым вызовом
создаётся копия одинакового для обоих методов входа вне замера.
Перемешивание воспроизводится с seed 7.

| N | Вход | makeheap_n_log_n, мс | makeheap, мс |
| ---: | --- | ---: | ---: |
| 10 000 | По убыванию | 7,658 | 2,060 |
| 10 000 | Перемешанный | 1,341 | 1,870 |
| 40 000 | По убыванию | 36,345 | 8,128 |
| 40 000 | Перемешанный | 5,564 | 7,572 |
| 160 000 | По убыванию | 164,469 | 32,405 |
| 160 000 | Перемешанный | 23,012 | 30,858 |

На убывающем входе преимущество `makeheap` выросло примерно с 3,7 до
5,1 раза. При случайном порядке просеивание вверх часто заканчивается
после нескольких сравнений, и в этих замерах оно оказалось быстрее.
Асимптотические оценки описывают рост затрат в худшем случае.
