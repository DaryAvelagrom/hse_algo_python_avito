# Iterative

## Идея

Итеративный mergesort начинает с отсортированных блоков длины 1.
За один проход он попарно сливает соседние блоки, затем удваивает
их длину. После последнего прохода весь массив образует один
отсортированный блок.

Итеративный quicksort выполняет разбиение вокруг опорного элемента,
сохраняет границы большей стороны в стеке и сразу обрабатывает меньшую.
Опорный элемент уже занимает итоговую позицию. Когда стек опустеет,
все стороны каждого разбиения будут отсортированы.

## Исполнение

Обе функции возвращают отсортированную копию. Они используют `merge`
и `partition` из Compare. В mergesort последний блок может быть короче
текущей ширины. Если у блока уже нет соседа справа, на этом проходе он
остаётся как есть. В quicksort границы отрезков хранятся в списке `stack`.
Рекурсивных вызовов в этих функциях нет.

## Визуализация

Mergesort для `[5, 2, 4, 1, 3]`.

| Ширина перед проходом | Слияния | Массив после прохода |
| --- | --- | --- |
| 1 | `[5] + [2]`, `[4] + [1]` | `[2, 5, 1, 4, 3]` |
| 2 | `[2, 5] + [1, 4]` | `[1, 2, 4, 5, 3]` |
| 4 | `[1, 2, 4, 5] + [3]` | `[1, 2, 3, 4, 5]` |

Quicksort на том же массиве. В стеке хранятся полуоткрытые отрезки.

| Шаг | Массив | Отложенные отрезки |
| --- | --- | --- |
| Снять начальный отрезок `[0, 5)` | `[5, 2, 4, 1, 3]` | пусто |
| Разбить по `3` и перейти к правой стороне | `[2, 1, 3, 5, 4]` | `[0, 2)` |
| Разбить правую сторону по `4` | `[2, 1, 3, 4, 5]` | `[0, 2), [3, 3)` |
| Снять пустой отрезок, затем разбить `[0, 2)` по `1` | `[1, 2, 3, 4, 5]` | `[1, 2)` |
| Снять отрезок длины 1, работа закончена | `[1, 2, 3, 4, 5]` | пусто |

## Сложность

- Mergesort работает за `O(n log n)`. Ширина удваивается на каждом
  проходе, один проход занимает `O(n)` времени. Дополнительная память
  для буфера и срезов составляет `O(n)`.
- Quicksort работает за `O(n log n)` в среднем на случайных перестановках
  различных элементов и за `O(n²)` при последовательных крайних разбиениях.
  Стек занимает `O(log n)` памяти. При каждом вложенном откладывании
  алгоритм спускается в меньшую сторону, длина которой не больше
  половины текущей. Когда эта сторона закончена, большая извлекается
  из стека и освобождает место.
- С учётом возвращаемой копии обе сортировки используют `O(n)` памяти.
