# Compare

## Идея

Mergesort делит массив пополам, рекурсивно сортирует половины и сливает их.
При слиянии на очередное место берём меньший из первых оставшихся
элементов двух половин. Так на каждом шаге выбирается минимум из всех
оставшихся элементов.

Quicksort берёт последний элемент отрезка в качестве опорного.
После `partition` слева от опорного лежат элементы строго меньше него,
а справа лежат элементы больше или равные ему. Опорный уже на своём
месте. Когда обе стороны отсортированы, весь отрезок тоже отсортирован.

## Исполнение

`mergesort(nums)` и `quicksort(nums)` возвращают отсортированную копию.
Границы отрезков полуоткрытые, `[left, right)`. Mergesort выделяет один
буфер для всех слияний. Quicksort рекурсивно обрабатывает меньшую
сторону, затем продолжает с большей в том же вызове. Отрезки длины
0 или 1 уже отсортированы.

Декоратор `measure_time` измеряет время вызова через `perf_counter` и
возвращает пару из результата функции и времени в секундах.
`compare_times` берёт медиану пяти замеров для каждой сортировки.
В замер входит создание копии входа. Декоратор оборачивает внешний вызов
целиком, поэтому время рекурсии тоже учитывается.

## Визуализация

Для массива `[5, 2, 4, 1, 3]` mergesort выполняет такие слияния снизу вверх.

| Шаг | Левая половина | Правая половина | Результат |
| --- | --- | --- | --- |
| 1 | `[5]` | `[2]` | `[2, 5]` |
| 2 | `[1]` | `[3]` | `[1, 3]` |
| 3 | `[4]` | `[1, 3]` | `[1, 3, 4]` |
| 4 | `[2, 5]` | `[1, 3, 4]` | `[1, 2, 3, 4, 5]` |

На том же массиве quicksort ставит `3` на своё место. При равных
размерах сторон рекурсивно обрабатывается правая.

| Шаг | Действие | Массив |
| --- | --- | --- |
| 1 | Разбиение всего массива относительно `3` | `[2, 1, 3, 5, 4]` |
| 2 | Рекурсивное разбиение `[5, 4]` относительно `4` | `[2, 1, 3, 4, 5]` |
| 3 | Разбиение `[2, 1]` относительно `1` в исходном вызове | `[1, 2, 3, 4, 5]` |

## Сложность

- Mergesort работает за `O(n log n)`. На каждом из `O(log n)` уровней
  слияния обрабатывают суммарно `n` элементов. Буфер и временные срезы
  занимают `O(n)`, стек рекурсии занимает `O(log n)`.
- Quicksort работает за `O(n log n)` в среднем на случайных перестановках
  различных элементов и за `O(n²)` в худшем случае. Если опорный каждый
  раз оказывается крайним, разбиения просматривают отрезки длины
  `n, n − 1, …, 2`. Стек занимает `O(log n)` даже в худшем случае,
  потому что рекурсивный вызов получает не больше половины элементов.
- С учётом возвращаемой копии обе сортировки используют `O(n)` памяти.

## Тесты

`test_compare.py` проверяет обе сортировки на пустом массиве, одном элементе,
повторах, отрицательных числах, упорядоченных и случайных данных.
Отдельные тесты проверяют декоратор и формат результатов замера.

Для замера запустите из корня репозитория `python -m homework_6.compare.algo`.
Ниже результаты одного запуска для массивов длины 1500.

| Вход | Mergesort, мс | Quicksort, мс |
| --- | ---: | ---: |
| По возрастанию | 1,131 | 57,257 |
| По убыванию | 1,242 | 37,650 |
| Все элементы равны | 1,190 | 18,652 |

На этих входах выбранный опорный делит отрезок на пустую сторону и
сторону из почти всех оставшихся элементов. Точные замеры зависят
от машины и нагрузки.
