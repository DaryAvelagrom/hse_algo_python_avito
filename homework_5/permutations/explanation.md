# Permutations

## Идея

Строим перестановку слева направо. На каждом шаге выбираем любой ещё не
использованный элемент, рекурсивно достраиваем продолжение и отменяем выбор.
Это перебор с возвратом - backtracking.

## Исполнение

`permutations(nums)` возвращает список списков и сразу печатает стек
рекурсивных вызовов через `tracer` из первой задачи.

`path` хранит текущий префикс, `used` отмечает занятые индексы исходного массива.
Добавляем элемент в `path`, помечаем индекс, вызываем `backtrack`.
После возврата удаляем последний элемент и снимаем отметку.
Когда длина префикса равна длине массива, сохраняем **копию** `path`.
Иначе все результаты ссылались бы на один изменяемый список.

На каждом уровне перебираются все свободные индексы. Поэтому любой порядок
индексов будет построен, а два разных пути выбора индексов не совпадут.
Для различных исходных значений это даёт все `n!` различных перестановок.

Входной массив не меняется. Пустой массив имеет одну перестановку - пустую:
результат `[[]]`. Если во входе есть одинаковые значения, переставляются их
позиции, поэтому одинаковые списки могут повторяться. Например, `[1, 1]`
даёт `[[1, 1], [1, 1]]`. Удаление повторов условием не задано.

## Визуализация

Дерево выбора для `[1, 2, 3]`:

```text
[]
├── [1]
│   ├── [1, 2] → [1, 2, 3] → сохранить, отменить выбор 3 и 2
│   └── [1, 3] → [1, 3, 2] → сохранить, вернуться к []
├── [2]
│   ├── [2, 1] → [2, 1, 3] → сохранить
│   └── [2, 3] → [2, 3, 1] → сохранить
└── [3]
    ├── [3, 1] → [3, 1, 2] → сохранить
    └── [3, 2] → [3, 2, 1] → сохранить
```

Начало реального вывода декоратора:

```text
-> backtrack([])
  -> backtrack([1])
    -> backtrack([1, 2])
      -> backtrack([1, 2, 3])
      <- backtrack = None
    <- backtrack = None
    -> backtrack([1, 3])
      -> backtrack([1, 3, 2])
      <- backtrack = None
    <- backtrack = None
  <- backtrack = None
```

`None` - результат вспомогательной функции: она добавляет перестановки в
`result`, а не возвращает их сама. Завершённая перестановка видна в аргументе
самого глубокого вызова. Весь список возвращает внешняя `permutations`.

## Сложность

Для `n` различных элементов есть `n!` ответов длины `n`.
Копирование ответов требует `O(n * n!)` времени. Перебор свободных индексов
также укладывается в эту оценку. Глубина рекурсии - `O(n)`.

Без учёта трассировки дополнительная память - `O(n)` для `path`, `used`
и стека. Ответ занимает `O(n * n!)` памяти.

С трассировкой при целых числах ограниченной длины время остаётся
`O(n * n!)`: на вызов печатается префикс и отступ длины `O(n)`.
Обёртки на активном пути сохраняют строки префиксов и отступов,
поэтому дополнительная память с декоратором - `O(n²)`.
Итого с результатом - `O(n * n! + n²)`. Вывод хранится внешней средой,
а не алгоритмом. Для чисел с длинными представлениями стоимость вывода
дополнительно зависит от их длины. Для `n = 0` время и память - `O(1)`.
