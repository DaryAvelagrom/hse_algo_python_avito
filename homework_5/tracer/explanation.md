# Tracer

## Идея

Декоратор оборачивает рекурсивную функцию и хранит текущую глубину вызовов.
Перед вызовом печатаем имя и аргументы, после - возвращённый результат.
Два пробела на каждый уровень показывают стек: более глубокий вызов начинается правее.

## Исполнение

`@tracer` заменяет функцию обёрткой. Рекурсивный вызов по тому же имени
тоже проходит через неё, поэтому видны все уровни рекурсии.

1. Формируем строку аргументов, включая именованные, через `repr`.
2. Выводим `->`, имя функции и аргументы с текущим отступом.
3. Увеличиваем глубину и вызываем исходную функцию.
4. При обычном завершении печатаем `<-` и результат, возвращаем его без изменений.
5. При исключении печатаем `!!` и передаём то же исключение выше.
6. В `finally` уменьшаем глубину при любом завершении.

Таким образом, значение глубины соответствует числу ещё не завершённых
вызовов этой функции. `finally` восстанавливает его и после ошибки,
поэтому следующий независимый вызов снова начинается без отступа.
`functools.wraps` сохраняет имя и документацию исходной функции.
У каждой декорированной функции свой счётчик; реализация рассчитана на
обычную синхронную рекурсию одной функции, без параллельных вызовов и генераторов.

## Визуализация

Для `factorial(4)` получаем:

```text
-> factorial(4)
  -> factorial(3)
    -> factorial(2)
      -> factorial(1)
      <- factorial = 1
    <- factorial = 2
  <- factorial = 6
<- factorial = 24
```

Сначала стек растёт: `4 → 3 → 2 → 1`. Базовый случай возвращает `1`.
Далее на обратном пути вычисляются `2 * 1`, `3 * 2`, `4 * 6`.
Возврат всегда имеет такой же отступ, как соответствующий вход.
Для ветвящейся рекурсии после возврата из первой ветки глубина уменьшается,
а следующая ветка начинается на том же уровне.

## Сложность

Пусть `C` - количество вызовов, `d` - максимальная глубина,
`L` - суммарная длина выведенных строк. Дополнительное время декоратора -
`O(C + L)`, если преобразование аргументов и результата в `repr` линейно
по длине представления. Сам алгоритм внутри функции оценивается отдельно.
При коротких аргументах отступы дают верхнюю оценку `O(C * d)`.
Произвольные пользовательские реализации `__repr__` могут стоить дороже.

Служебные данные обёрток без строк занимают `O(d)` памяти.
Каждый активный вызов сохраняет свой отступ и представления аргументов.
Только отступы суммарно занимают `O(d²)`; к ним добавляется размер
сохранённых строк аргументов и текущего представления результата.
Вывод идёт сразу в стандартный поток: история вызовов в декораторе не хранится.
