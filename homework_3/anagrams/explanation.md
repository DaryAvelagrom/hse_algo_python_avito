# Anagrams

## Идея

Два слова являются анаграммами, если они состоят из одинаковых букв в одинаковом количестве, но буквы могут стоять в разном порядке.

Считаем, сколько раз встречается каждая буква алфавите встречается в этом слове. Для каждого слова создаём список из 26 счётчиков. Этот набор используем как ключ словаря. Слова с одинаковым набором являются анаграммами.

Эо решение работает? потому что анаграммы отличаются только порядком букв.

Если два слова являются анаграммами, то количество каждой буквы в них одинаковое. Значит, после подсчёта букв для них получится один и тот же набор из 26 значений.

## Исполнение

Для каждого слова создаём список из 26 нулей. Каждая позиция отвечает за одну букву английского алфавита.

Номер позиции для символа получаем как порядок буквы в алфавите, считая, что а - нулевая.

Проходим по всем символам слова и увеличиваем соответствующий счётчик, который будет ключем в словаре анаграмм.

Если такой ключ уже есть в словаре, добавляем слово в существующую группу. Если ключа ещё нет, создаём новую группу.

После обработки всех слов значения словаря и будут искомыми группами анаграмм.

## Сложность

Пусть `n` — количество слов, а `k` — максимальная длина одного слова.

Для каждого слова мы один раз проходим по всем его символам. Для слова длины `k` это занимает:

```text
O(k)
```

Также для каждого слова создаётся и преобразуется в `tuple` массив длины 26. Так как 26 — константа, эта операция занимает:

```text
O(1)
```

относительно размера входных данных.

Поэтому для `n` слов общая временная сложность:

```text
O(n * k)
```

По памяти алгоритм хранит словарь с группами анаграмм, все исходные слова внутри этих групп и для каждой группы ключ из 26 чисел.

Если всего `n` слов, а максимальная длина слова равна `k`, то суммарно на хранение всех строк требуется:

```text
O(n * k)
```

Ключ для каждой группы имеет фиксированный размер 26, то есть занимает `O(1)` памяти. Даже если все `n` слов попадут в разные группы, память на ключи будет:

```text
O(n)
```

Дополнительно при обработке одного слова создаётся список из 26 счётчиков, то есть:

```text
O(1)
```

дополнительной памяти, поэтому он не меняет итоговую асимптотику.

## Визуализация

Возьмём

```text
["State", "taste", "below", "elbow", "aabb", "baba", "Stone"]
```

Сначала приводим слова к нижнему регистру и считаем количество каждой буквы.

```text
State
 ↓
state
 ↓
a:1, e:1, s:1, t:2
 ↓
key_1
```

```text
taste
 ↓
taste
 ↓
a:1, e:1, s:1, t:2
 ↓
key_1
```

Оба слова получили одинаковый ключ:

```text
key_1 -> ["State", "taste"]
```

Теперь:

```text
below
 ↓
below
 ↓
b:1, e:1, l:1, o:1, w:1
 ↓
key_2
```

```text
elbow
 ↓
elbow
 ↓
b:1, e:1, l:1, o:1, w:1
 ↓
key_2
```

Получаем:

```text
key_2 -> ["below", "elbow"]
```

Далее:

```text
aabb
 ↓
a:2, b:2
 ↓
key_3
```

```text
baba
 ↓
a:2, b:2
 ↓
key_3
```

Получаем:

```text
key_3 -> ["aabb", "baba"]
```

Для слова:

```text
Stone
 ↓
stone
 ↓
e:1, n:1, o:1, s:1, t:1
 ↓
key_4
```

оно получает отдельный ключ.

После обработки всех слов:

```text
key_1 -> ["State", "taste"]
key_2 -> ["below", "elbow"]
key_3 -> ["aabb", "baba"]
key_4 -> ["Stone"]
```

Итог:

```text
[
    ["State", "taste"],
    ["below", "elbow"],
    ["aabb", "baba"],
    ["Stone"]
]
```
